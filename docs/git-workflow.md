# Правила роботи з Git

## Модель гілкування

main — погоджений стан артефактів проєкту. Короткоживучі тематичні гілки — окремі зміни документації, вимог, коду або тестів.

Зміни людини й агента для навчального конфлікту виконуються у двох гілках від спільного стану main. Злиття в main здійснюється після перевірки змін.

## Повідомлення комітів

Формат: префікс: [джерело зміни] короткий опис

spec: — задум системи та специфікації.
test: — тести й тестові артефакти.
feat: — реалізація функціональності.
docs: — документація та журнали роботи.
gate: — рішення контрольних точок.

[human] — ручна зміна або рішення студента.
[agent] — зміна файла, безпосередньо виконана кодинговим агентом.

Коміти створює студент від власного імені.
Позначка [agent] відображає походження зміни, а не підмінює ідентифікаційні дані автора коміту.

Зміни агента перевіряються через git diff перед комітом.
